# Contributing

Contributions are welcome.

1. Fork the repository and create a focused branch.
2. Keep signing keys, APKs, device captures, and school-specific URLs out of commits.
3. Run the schedule test executable and build the Android project.
4. Describe device model, Android version, kiosk mode, and verification performed in the pull request.

Changes involving lock task, boot recovery, alarms, WebView lifecycle, or system UI should be tested on physical hardware. Emulator-only results are not sufficient for those areas.
